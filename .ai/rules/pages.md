# Pages

## Bank band row actions: Match (register pick mode) and New transaction
Each unmatched bank row in the account page band has two hover actions. "Match" sets matchingBankTransaction: the chosen band row highlights, other band rows dim, and register lines that can take a link (status-bearing, no bank_transaction) become clickable (role=button, Enter works, accent hover) while the rest dim; clicking POSTs bank-transactions/{id}/match with that posting id and reloads band + register. Esc, the row's Cancel, or a completed match exit the mode; 409/422 surface via alert(). "New transaction" opens TransactionForm with the bankTransaction prop (see requests-financial rule). Proposed exact matches never appear in the band — they render on the register line with ✓/✕.

## Register scrolls instead of paging; the API stays paginated
The account register appends pages as the user scrolls: an IntersectionObserver (400px root margin) on a sentinel div after the list calls loadMorePostings, which keeps fetching page loadedPages+1 while the sentinel stays visible and pages remain. PostingController::index is still paginate(50) — the SPA just accumulates. loadPostings() re-reads every loaded page in parallel and concatenates, so status changes, matches and unmatches update in place without losing scroll position; resets (account change, hide-reconciled toggle) set loadedPages back to 1. Assertion markers older than the loaded span wait until their day scrolls in; the newest marker always shows because page 1 is always loaded. PaginationBar remains for the journal, which still pages.

## Parent account pages roll up their subtree
When the loaded accounts list shows the account has children, AccountPage sets includeDescendants and passes include_descendants=1 to GET postings, GET lots and GET accounts/{id}/balances (each scoped server-side via Account::subtreeIds()). Balances come back per (account, commodity); the page sums per commodity for the header/holdings and per direct child for the Sub-accounts list (market value via money.ts marketValue, "—" when any holding is unpriced). The register mixes every descendant's postings strictly by date with one running balance per commodity, adding an Account column that shows the path relative to the page's account and links to it. Bank-row matching (canMatch) only targets the page account's own postings since a bank row belongs to one account. New transaction renders only when the account is a leaf or allow_postings is set; the assertion button keeps the asset/liability rule. Own-account behaviors (bank band, SimpleFIN sync, assertions) never roll up.

## Income and expense pages are period-scoped; balance-sheet accounts stay all-time
Income/expense accounts have no meaningful all-time balance, so AccountPage scopes them to a period (Period = year | month | all; default this calendar year, reset on every account load). The header total reads "Total · 2026" (or 2026-09 / All time) and shows $0 when the period is empty; the only period control is the period block under the header: a year row (an All time cell, then every year from the earliest posting through today) above a month row (Jan through the current month for this year, all twelve for other years) built from GET accounts/{id}/period-totals?group=year|month (subtree-aware). Cells share the .period-cell class in app.css: label top-left, value right-aligned (muted dash when empty), and a 2px accent bar sized against the row's largest absolute value — a single-series bar, so no legend and no tooltip. There is no header switcher and the rows carry no headings. The window is passed as from/to to GET postings (running balance restarts at zero) and from/as_of to GET accounts/{id}/balances; the month strip follows the selected period's year. Asset, liability and equity pages ignore all of this and keep the all-time balance and the Hide reconciled toggle, which is hidden on scoped pages since their postings carry no status. Never close periods with journal entries — the period is a report window, not a ledger event.
